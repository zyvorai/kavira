KAVIRA · How a compile works

Six steps. Execution decides.

The proposer lists competing explanations. The runner decides whether the failure reproduces and whether the repair holds. If the symptom does not reproduce, KAVIRA stops.

01

Read evidence

An evidence bundle: captured limit, peak, restarts, latency, deploy change.

02

Propose

Competing explanations. None of them is authoritative.

03

Run the original

An isolated, bounded reconstruction of the captured condition.

04

Stop if it does not reproduce

No repair package. There is nothing to repair yet.

05

Change one factor

Run the repair arm. Same workload, one difference.

06

Write the package

Patch, regression test, measurements, and reproduction steps, only if the repair held.

repair_held

Reproduced, then the repair held.

not_reproduced

The symptom did not reproduce.

repair_failed

Reproduced, but the repair did not hold.

unsupported

Outside the three v0 classes.
