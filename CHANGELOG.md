# Changelog

## Unreleased

- **Confidence.** `kavira repeat -f B -n 20` and `GET /api/v1/incidents/{id}/confidence`: reproduction and repair rates with 95% Wilson intervals; `not_reproduced` only after 20 clean runs, otherwise `inconclusive`; `flaky` when runs disagree. No seed on purpose: the runners have no random source.
- **Minimizer.** `kavira minimize` and `.../minimize`: delta debugging (ddmin) over config-diff keys, network factors or workload requests, with the runner as oracle; reports 1-minimality and re-verifies the result. Never claims a global minimum or a production cause.
- **Postmortem draft.** `kavira postmortem` and `.../postmortem.md`: blameless Markdown that separates demonstrated, captured and hypothesis, states no root cause or repair unless execution showed it, and escapes all bundle text. Bundles may carry an optional `timeline`.
- **Regression export.** `kavira export` and `.../regression.zip`: a dependency-free `regress.sh` that fails on the captured condition and passes on the repair; `repair_held` only.
- **Console.** An **Analyze** tab per incident for the four above.
- **Hostile input.** Bundles are now bounded before anything runs (size, text, ids, timeline, config keys, requests, total allocation, network attempts/delay/timeout). Previously a bundle could ask the runner for terabytes or hours. Repaired network conditions read by `kavira test` are re-validated; a repair that would leave the limits is `repair_failed`, not run. `kavira compile` no longer reads a whole oversize file.
- **Docs.** `docs/RESEARCH.md` (prior art, ranked ideas, claims marked fetched or unverified) and `docs/ANALYSIS.md`; `examples/analysis/`.
- **Toolchain upgrade.** `go.mod` now says `go 1.26` (was 1.23); CI runs the test job on a Go 1.26.x / 1.27.x matrix and the other jobs on 1.27.x; CI Node 22 -> 24; Playwright pin 1.49.1 -> 1.65.1 (the e2e suite passes on it); runtime image `distroless/static-debian13:nonroot` (was debian12; the build image `golang:1.27-alpine` was already current); `sigstore/cosign-installer` v3 -> v4.1.3; README Go badge 1.26+. Every other action was already on its latest major. Held back: the cosign pin is an exact tag because upstream publishes no floating `v4` tag; Actions stay tag-pinned (not SHA-pinned) to match the existing style; `deploy/` pins the KAVIRA image itself, which is version-synced, so there was nothing to bump.
- **Disk pressure class.** Fourth supported incident: bounded write workload under a captured volume quota, with raise-quota and rotate/flush repair arms (`examples/disk-pressure.json`).
- **CLI.** `kavira compile -d DIR` batch-compiles every `*.json` bundle; `kavira test -d DIR` retests every repair package; `--format junit|github|json` for CI; `kavira summarize -f verdict.json` prints a human one-pager.
- **API.** `GET /api/v1/incidents/{id}/package.zip` downloads the repair package when execution confirmed a repair.
- **Site and live demo on GitHub Pages** (`https://zyvorai.github.io/kavira/`). A landing page with an animated compile pipeline, a verdict explorer, theme-aware screenshots, and copy buttons; and `/demo/`, the *real* console running without a server on API responses that `scripts/build-site.sh` records from a throwaway local `kavira serve`, so the demo cannot drift from the API. `scripts/site-check.cjs` drives both under the real `/kavira/` sub-path in CI.
- Console: toasts no longer stretch to the width of the longest message.
- **Console rebuilt on the Zyvor UX contract.** Hash routes (`#/incidents/<id>/<tab>`) so every view is linkable and survives reload; real links with `aria-current`; a selected-incident chip; search, verdict filter, and sortable incident table; evidence now shows the captured bundle and measurements; experiments explain the verdict; repairs add Copy and download of `regression_test.json` or the whole package; a "Compile your own bundle" dialog; an audit view that verifies the hash chain; empty, loading, and error states everywhere; keyboard shortcuts (`g o/i/e/x/r/a`, `/`, `?`). A Playwright suite covers every route in light, dark, and 390px.
- **Login redesigned.** No prefilled credentials, no password in the error text, distinct "wrong password", "server unreachable", and "session expired" messages. The demo-gate hint shows only while the gate is on.
- **Theme.** Tokens shared with Netra, `prefers-color-scheme` honored, no flash of the wrong theme (`/theme.js` runs before first paint), proper focus rings, 44px targets, reduced motion.
- **Security.** Fixed stored XSS: every server string reaching the DOM is now escaped by default. Constant-time credential check, strict CSP and security headers, `Secure` cookie option, server timeouts and graceful shutdown, JSON-only login/compile, 413 on oversize bundles, sorted incidents, a warning when the default password is exposed beyond loopback.
- **HTTPS.** `kavira serve -tls-cert/-tls-key` and `-tls-self-signed DIR [-tls-host …]` (generated once, reused, regenerated when the host changes or the certificate nears expiry). Serving TLS forces a `Secure` session cookie; plain HTTP beyond loopback prints a warning. `scripts/deploy-remote.sh` deploys HTTPS by default, sends rsync deltas, and takes `--demo` (keep admin / Admin@321 on a test host) and `--http`.
- **API.** `GET /api/v1/session` (quiet auth probe), `demo_gate` in health, fixtures now describe class and symptom, `chain_ok` in audit, JSON errors.
- **Project.** README with hero, screenshots, demo, and cards; social images and favicon; landing site; release, CodeQL, and Dependabot workflows; Docker healthcheck; kustomize and compose manifests; `scripts/deploy-remote.sh`; full Apache-2.0 text; SECURITY, CONTRIBUTING, AGENTS.
